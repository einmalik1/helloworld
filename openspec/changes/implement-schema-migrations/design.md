## Context

ADR 0001 already decided: SQL SoT → drizzle generator stage → `packages/modules`; Better Auth CLI owns a separate auth schema file; `drizzle-kit migrate` is the only apply path; no Nest runtime DDL. Baseline specs under `openspec/specs/schema-migrations/` encode that intent. Generators today stop at `nest_dto`; `packages/modules` is an empty scaffold; no `drizzle.config.ts`, migrations folder, or `db:*` scripts exist.

In-force ADRs constraining this design: **0001** (schema/migrations — implement, do not reopen), **0003** (Better Auth product choice — auth tables stay Better Auth owned). ADRs 0002/0004–0007 are out of scope here.

## Goals / Non-Goals

**Goals:**

- Wire the SQL → Drizzle TS → drizzle-kit → migrate pipeline end-to-end in-repo.
- Pin paths and script names so Nest wiring (#39) can import schema without inventing ownership.
- Ship an initial migration that creates domain tables (+ auth tables from the auth schema scaffold).
- Document Coolify pre-deploy = `pnpm db:migrate`.

**Non-Goals:**

- Nest `DatabaseModule` / `DatabaseService` / health / auth HTTP / OpenAPI (#39 / later Wave B).
- Full Better Auth product wiring (`implement-auth-better-auth`).
- Changing `schema.sql` domain shape (except if generator discoverability requires comments — avoid).
- Replacing ADR 0001 or merging auth DDL into `schema.sql`.
- Host Compose as the agent smoke plane (Coolify **test** remains the shared plane; local migrate against laptop Compose is allowed for developers).

## Decisions

1. **Domain schema path:** `packages/modules/src/database/schema/` (one file per table + `index.ts`), generated by Python/Jinja stage `drizzle` reading `schema-model.json`. Config in `spark/repo-profile.yaml` → `generators.drizzle.out_dir`.

2. **Auth schema path:** `packages/modules/src/database/auth-schema.ts`. Hand-committed Better Auth–shaped tables (user/session/account/verification + api-key plugin tables as required by Better Auth 1.7.7 + `@better-auth/api-key`). Document regenerate with `@better-auth/cli generate --output …`. Not produced by the Python generator.

3. **drizzle-kit config:** repo-root `drizzle.config.ts` (dialect postgresql, `schema` = domain index + auth-schema, `out` = `packages/modules/drizzle`). Credentials from `DATABASE_URL` (dotenv from root `.env`).

4. **Scripts (root `package.json`):**
   - `generate:drizzle` → `python3 spark/generators/run.py --only drizzle` (and include `drizzle` in default `generate:code` stage list)
   - `db:generate` → `drizzle-kit generate`
   - `db:migrate` → `drizzle-kit migrate`
   - Optional `db:studio` deferred unless trivial

5. **Dependencies:** add `drizzle-orm` **0.45.3** and `drizzle-kit` **0.31.11** per tech-stack (kit as root or modules `devDependency`; orm as modules dependency). Use `postgres` package only when Nest DB lands if not already needed by kit migrate — drizzle-kit migrate uses its own driver; prefer kit defaults without forcing Nest wiring now.

6. **Initial migration:** after first generate of domain TS + auth-schema, run `db:generate` once and commit SQL under `packages/modules/drizzle/`. CI/local apply via `db:migrate`.

7. **Docs:** update `packages/modules/README.md` Database section (remove TBD/intent for ownership + commands), `spark/generators/README.md` stage table, `openspec/tech-stack.md` Database / generators rows (script names no longer TBD), note Coolify pre-deploy command. Fix stale `spec/` path pointers only where this change already edits those lines.

8. **Smoke for this ticket:** `pnpm generate:drizzle` succeeds; `packages/modules` typecheck/build with generated schema; `drizzle-kit generate` dry-check or migrate against available Postgres if local/Coolify URL present — otherwise document migrate + run generator/typecheck as the gate when DB is unreachable from the agent host.

## Risks / Trade-offs

- **[Risk] Auth CLI output drifts from hand scaffold** → Mitigation: README documents regenerate command; Wave B auth ticket re-runs CLI and generates a follow-up migration.
- **[Risk] Generator SQL→Drizzle mapping incomplete for edge types** → Mitigation: map types used in current `schema.sql` (uuid, text, timestamptz, FKs, unique, check, indexes); extend when new SQL types appear.
- **[Risk] Agent host cannot reach Coolify Postgres** → Mitigation: commit migration SQL; smoke generator + kit config + typecheck; migrate when `DATABASE_URL` is reachable.
- **[Trade-off] Auth schema committed vs only CLI** → Commit scaffold so migrate works before auth package wiring exists; CLI remains SoT for future regen.

## Migration Plan

1. Land generator + schemas + drizzle-kit + scripts + docs + initial migration SQL on the automation branch.
2. Operators / Coolify: set `DATABASE_URL`, run `pnpm db:migrate` as pre-deploy before api/worker traffic.
3. Rollback: reverse migration not required for v1 empty DBs; restore previous migration set from git if needed.
